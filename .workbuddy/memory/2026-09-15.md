## 三、内存排查（05:56–06:15）—— 结论与之前猜的完全不同

> 用户问 feGaussianBlur 是哪部分 → **纠正：项目里根本没有 feGaussianBlur**，
> 辉光的真实实现是 `radialGradient(gGlow) + 两个大圆(r=135/118) + mix-blend-mode:screen`。
> 之前"查 glow 滤镜缓冲区"的建议作废。

**测量方法**：给 main.js 加了三个 env 开关（都保留为开发功能）：
- `FAIRYPET_MEASURE=<毫秒>` → `app.getAppMetrics()` 打印各进程类型/内存/CPU 后退出
- `FAIRYPET_OPAQUE=1` → 透明窗临时改不透明（A/B 用）
- `FAIRYPET_UI_DIR=<目录>` → 指向 ui 副本做 A/B

**实测（app.getAppMetrics，12s 稳定后）**：
| 进程 | rss |
|---|---|
| GPU | **361MB（峰值 397-401）← 唯一大头** |
| Browser | 134MB |
| Tab（渲染=页面本体） | **82-84MB** |
| Utility | 47MB |

**A/B 全部无效（噪声级，勿再试）**：隐藏辉光 / 去掉 mix-blend-mode / 去掉 .float 浮动动画+will-change / 透明改不透明（360.9 vs 359.3）。
`--in-process-gpu`：625→578MB，只省 47MB 且牺牲稳定性，不采用。

**结论**：
1. 页面内容（SVG 动画+辉光）根本不是内存问题，渲染进程只有 84MB。
2. 361MB 的 GPU 进程是**本受限会话 GPU 驱动不可用 → Chromium 回退 SwiftShader 软件合成**的固定开销
   （启动日志有 `GPU process exited unexpectedly: exit_code=1` 循环佐证）。
3. 用户正常桌面（GPU 正常）预期总量 ~250-330MB。**验证方法**：
   `FAIRYPET_MEASURE=15000 npm start`，看 GPU 行是否 ~50-150MB；
   若用户机器上 GPU 行也是 300+MB ⇒ 其 GPU 加速也静默失败，再做软件渲染适配。
4. Electron 地板 = Browser+Tab+Utility ≈ 263MB（Tauri 全程 72MB 的差距主要在这里）。

**排查方法论教训**：
- "哪个进程吃内存"必须用 `app.getAppMetrics()` 按 type 拆开看，别看任务管理器四个同名 electron.exe 猜。
- 本会话里 Electron 启动有**竞态**（GPU 崩溃循环偶发 FATAL 退出）：自动化测试必须带重试 + FindWindow 等窗口出现。
- `node cli.js script.js` / 脚本直跑模式下 `require('electron')` 会解析到 npm 包（返回路径字符串），
  `app` 是 undefined —— mini-app（目录+package.json）或直接跑 electron 二进制才行。
